# Security findings – HR-MS repository (baseline review)

Found while building this DevOps project. **The "Before Day 1" step in LAB-GUIDE.md fixes the critical items before any pipeline runs.** This file doubles as a teaching example of a real finding register.

| ID | Severity | Finding | Status / fix |
|---|---|---|---|
| SEC-01 | **Critical** | `.env.production` and `deploy-hrms/runtime-package/.env.production` are **committed to git**. They hold a live database URL with its password, a JWT signing secret and a Redis URL. Anyone with repo access, now or in the past, can read them. | **Rotate** the DB password and the JWT secret now. Run `git rm --cached` on both files, add them to `.gitignore`, and rewrite history with `git filter-repo` (see "Before Day 1" in LAB-GUIDE.md). Then move the values to Key Vault (`terraform/lab` + `scripts/env-from-keyvault.sh`). |
| SEC-02 | High | A `.env` file sits in the working tree. It is git-ignored, but people share it by hand. | Keep local only. Generate it from `.env.example`. |
| SEC-03 | High | Build zips and log bundles (`qode27-*.zip`, `*.log`, `qode27-logs*`) sit in the repo folder. They may contain env files and stack traces. | Delete them or move them out. They are excluded from the Docker context by `Dockerfile.dockerignore`. |
| SEC-04 | Medium | `JWT_SECRET` rotation logs every user out, and there is no key versioning. | Accept for now. Plan `kid`-based key rotation later. |
| SEC-05 | Medium | Key Vault and ACR have public endpoints (lab trade-off; see the `checkov.yaml` skips). | Prod: Premium ACR and Key Vault private endpoints, plus self-hosted agents in the VNet. |
| SEC-06 | Medium | The AKS API server is public (hosted agents). | Prod: authorised IP ranges or a private cluster with self-hosted agents. |
| SEC-07 | Low | `npm audit` runs in report-only mode in CI. | Make it blocking once the current backlog is fixed. |
| SEC-08 | Low | No ESLint config, so `next lint` cannot run in CI. | Add `eslint.config.mjs`, then add a lint step to `Validate`. |

## Controls already in place (show these to students)

- **Supply chain:** pinned base images, multi-stage builds, a non-root user (1001), a read-only root filesystem, trivy (HIGH/CRITICAL, fixable), an SPDX SBOM, and build-once-promote.
- **Secrets:** gitleaks in CI, Key Vault with RBAC, CSI sync with Workload Identity, secrets generated by Terraform (never typed by hand), and no ACR admin user or SP client secrets (OIDC).
- **Runtime:** Pod Security Standard *restricted*, dropped capabilities, seccomp RuntimeDefault, default-deny NetworkPolicies, and a private Postgres reachable only from the AKS subnet.
- **IaC:** checkov in the infra pipeline, `terraform plan` reviewed before an approved `apply` of the **saved** plan, and remote state with Entra ID auth (no storage keys).
